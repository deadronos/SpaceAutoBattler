# AI V2 Rollout Playbook

_Updated: 2025-09-22_

## Purpose

Document the guardrails and procedures required to enable the AI V2 decision system by default once intercept/reposition/regroup behavior stabilises. This playbook is aimed at engineers and QA coordinating staged rollouts across local, CI, and production-like environments.

## Feature Flag Controls

- Runtime toggle: `uiStore.ai.v2Enabled` (existing HUD switch) immediately flips between legacy and v2 behavior without resetting the simulation.
- Build/CI toggle: set `AI_V2_DEFAULT=on` in the environment before importing `src/game/config.ts`. The new helper in `AI_CONFIG` reads this flag and enables AI V2 on boot. Accepted truthy values: `on`, `true`, or `1` (case-insensitive).
- Safety check: leaving the flag unset (or set to any other value) keeps legacy AI as the default, ensuring hotfixes can disable v2 globally.

## Required Checks Before Enabling by Default

1. ✅ `npm run test` — executes the Vitest suite (determinism, scorer, executor, intercept/regroup selection, scenario harness).
2. ✅ `npm run perf:ai-budget` — asserts AI tick budget at 300 ships stays within the configured limit.
3. ✅ Scenario harness replay — `vitest run test/vitest/ai-scenario-harness.spec.ts` verifies escort defense, bomber intercept, and artillery retreat logs generated by `runAIScenario`.
4. ✅ Manual HUD spot-check — launch the build, enable "AI Debug" overlay, ensure intercept/reposition/regroup intents surface as expected.

For CI automation, run `npm run test:ci` which now chains Vitest and the perf budget guard.

## Scenario Harness Usage

- API lives in `test/support/aiScenarioHarness.ts` and exposes `runAIScenario(config)` returning deterministic logs for fixtures and tooling.
- Scenarios are configured via plain objects (ship hulls, positions, optional velocities/HP). See `test/vitest/ai-scenario-harness.spec.ts` alongside fixtures `ai-escort-scenario.json`, `ai-bomber-intercept-scenario.json`, and `ai-artillery-retreat-scenario.json` for reference scripts.
- To record a new golden log, run the harness with your config in Node (via `tsx` or a Vitest watch run), capture the JSON output, and update the corresponding fixture. Keep logs short (<10 ticks) to avoid bloating the repo.

## Troubleshooting & Rollback

| Symptom                    | Action                                                                                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Budget script fails        | Inspect `state.ai.metrics` counters in the HUD. Reduce `AI_CONFIG.maxPerTick`, widen LOD thresholds, or throttle scenario complexity.         |
| Scenario harness diff      | Run `vitest --run ai-scenario-harness.spec.ts --reporter verbose` to view the delta. Update fixtures only after confirming behavioral intent. |
| Non-deterministic commands | Ensure all randomness flows through `SeededRng`; check for stray `Math.random` or Date usage.                                                 |
| Need emergency rollback    | Clear `AI_V2_DEFAULT`, disable the HUD toggle, and redeploy. Legacy AI code path remains intact and fully covered by `ai-regression.spec.ts`. |

## Communication Checklist

- Announce rollout intent in release notes and link this playbook.
- Confirm QA sign-off on intercept/regroup behaviors with HUD overlay screenshots.
- Post-rollout, monitor perf dashboards for spikes in `ai.metrics.budgetHits`.

With intercept/reposition/regroup now implemented and under test, the system is gated behind deterministic fixtures, perf checks, and environment-based toggles—providing a clear, reversible path to enable AI V2 by default.
