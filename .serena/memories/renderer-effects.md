# renderer/effects.ts

**Memory name:** renderer-effects

Summary:
- Location: `src/renderer/effects.ts`
- Purpose: Lightweight wrapper and safety layer around postprocessing effects and readback pitfalls for WebGL/three.js. Provides an `EffectsManager` factory which either no-ops when `postprocessing` isn't available or creates a composer with RenderPass and optional passes (bloom, motion blur, DOF, AA, tone mapping).

Key exports and responsibilities:
- createEffectsManager(renderer, scene, camera): EffectsManager — returns an object with `render`, `resize`, `dispose`, and runtime toggles for bloom, motion blur, DOF, and a helper `addExplosionEffect`.
- applyGlobalPatches(): void — idempotent helper that patches WebGL readPixels behaviors on global prototypes and three.js prototypes to log and avoid synchronous readbacks that can stall the GPU.

Important implementation notes:
- Includes safe helpers: `getTempRT`, `blitToTemp`, `readPixelsSafe` to copy depth/texture data into a compatible temporary RGBA ubyte render target before reading pixels.
- Patches both the renderer instance and three.js prototype `readRenderTargetPixels` to redirect reads through a temporary RT when necessary. Also patches EffectComposer instances to intercept passes that perform depth reads (DepthCopyPass/DepthPickingPass) and replace synchronous reads with async or deferred reads.
- Uses defensive try/catch around all patches and postprocessing interactions to avoid breaking the render loop if `postprocessing` is missing or passes fail.
- Configurable flags (internal) to disable motion blur and depth-of-field by default to minimize risk.

Design decisions and patterns:
- Focus on safety and portability: avoids sync readPixels on drivers where that causes problems, and provides fallbacks to deferred sync reads when async APIs aren't available.
- Exposes small runtime API surface for game code to toggle effects without direct dependency on postprocessing types.
