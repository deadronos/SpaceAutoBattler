# TASK234 — Star Disk Animation Restoration

**Status:** Completed  
**Updated:** 2025-10-03

## Problem Statement

- Debug sessions that append `?copilot_debug=1` render the star disk with a static `MeshBasicMaterial`, preventing the main sequence shader from animating.
- The `iTime` uniform must advance every frame to keep the shader effects alive during both production and debug runs.

## Architecture Overview

- `StarDisk.tsx` owns a `THREE.Mesh` billboard that attaches `MainSequenceStarMaterial` generated by `createMainSequenceStarMaterial` and refreshed via `updateMainSequenceStarUniforms` inside `useFrame`.
- Debug helpers are gated behind a memoized `debugEnabled` flag derived from `window.location.search`. Forced material overrides are handled imperatively in the render loop by swapping `mesh.material`.
- Uniform updates rely on either the active simulation clock (`state.simulation`) or a local `fallbackTimeRef` that accumulates `delta` when simulation is unavailable.

## Data Flow

1. React render attaches `ShaderMaterial` to the mesh and registers a `useFrame` callback.
2. Each frame computes `elapsed` time from simulation or the fallback accumulator.
3. `updateMainSequenceStarUniforms` mutates the material uniforms with the new `time`, resolution, alignment, and textures.
4. Debug automation may request forced basic materials via `window.__copilot_forceBasicMaterialActive`; the loop swaps materials only when that flag is true.

```text
URL query -> debugEnabled ─┐
                          │
                          ├─> React render -> mesh.material (ShaderMaterial)
                          │                       │
                        window flags          useFrame loop
                          │                       │
                          └─> (optional) forced material swap
```

## Interfaces

- `StarDiskProps`: `config`, `size`, `opacity`, `distanceMultiplier`, `enabled`, optional `haze`/`boundary`.
- `MainSequenceStarUniformUpdate`: time, resolution, optional textures, roll, north, view alignment, haze, boundary.
- Debug helpers: `window.__copilot_forceBasicMaterialActive`, `window.__copilot_setStarBasicMaterial`, `window.__copilot_restoreStarMaterial`.

## Error Handling Matrix

| Scenario                                      | Detection                                        | Response                                                               |
| --------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| Shader creation fails                         | `createMainSequenceStarMaterial` throws          | Log warning and fall back to `<meshBasicMaterial>` (existing behavior) |
| Uniform update receives non-finite resolution | Guarded via clamping in `StarDisk`               | Clamp to safe defaults (1x1)                                           |
| Simulation absent                             | `gameState?.simulation` falsy                    | Use `fallbackTimeRef` accumulator                                      |
| Forced basic material requested               | `window.__copilot_forceBasicMaterialActive` true | Swap to cached `MeshBasicMaterial` via helper, revert when cleared     |

## Testing Strategy

- **Component Regression:** With `?copilot_debug=1`, render `StarDisk` and assert the mesh keeps a `ShaderMaterial` after a frame.
- **Uniform Timing:** Spy on `updateMainSequenceStarUniforms`, trigger multiple frame callbacks, verify monotonically increasing `time`.
- **Existing Debug Lockdown:** Re-run `test/vitest/star-disk-debug-lockdown.spec.tsx` to ensure helper scrubbing still passes.

## Implementation Plan

1. Remove the unconditional `forceBasicDevMaterial` branch so the shader remains attached even when `debugEnabled` is true.
2. Preserve debug helper geometry (axes, cube) behind `debugEnabled` only.
3. Add a new Vitest spec to confirm shader material retention and time progression with the debug flag set.
4. Adjust existing debug lockdown spec if expectations change (e.g., material assumptions).
5. Run targeted Vitest suites and TypeScript checks.

## Risks & Mitigations

- **Risk:** Material swap logic in `useFrame` may still enforce the Basic material if the debug flag remains active.  
  **Mitigation:** Ensure helpers only toggle the swap when explicit flags are set; tests cover the default debug case.
- **Risk:** Spy-based tests might rely on mocked `useFrame` semantics.  
  **Mitigation:** Reuse the custom frame callback harness already present in `star-disk-debug-lockdown.spec.tsx`.

## Rollback Plan

- Revert `StarDisk.tsx`, new spec, and memory updates to previous commit if regressions surface.
